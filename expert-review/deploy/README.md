# Постоянный запуск экспертной оценки

Приложение работает отдельным системным пользователем через Gunicorn на `127.0.0.1:8768`. Публичный HTTPS обслуживает существующий Caddy. Один процесс с четырьмя потоками выбран для SQLite и общего ограничения попыток входа внутри процесса. Доступ к приложению в обход Caddy с внешних интерфейсов не открывается.

## Каталоги

| Путь | Содержимое |
| --- | --- |
| `/srv/competence-review/releases/<revision>` | Неизменяемый снимок исходников |
| `/srv/competence-review/current` | Ссылка на действующий снимок |
| `/srv/competence-review/venv` | Python-окружение |
| `/etc/competence-review/server.env` | Домен и параметры запуска |
| `/var/lib/competence-review` | Постоянная база и ключ организатора |
| `/var/backups/competence-review` | Последние 14 проверенных архивов базы и ключа |

Каталоги с базой и резервными копиями доступны только служебному пользователю и root. Ключ, база и архивы не включаются в Git. Код хранится отдельно и доступен служебному пользователю только для чтения.

## Настройки

За основу берётся `server.env.example`. `REVIEW_DATA_DIR` обязателен и должен содержать абсолютный путь. `REVIEW_PUBLIC_HOST` — точный домен без `https://`, пути и порта. Пустое значение оставляет приложение доступным только под локальными именами для подготовки и проверки. `REVIEW_ENABLE_DEMO=0` отключает анонимное демо и скрывает его кнопку; реальные приглашения продолжают работать.

`wsgi.py` доверяет IP и схеме HTTPS от одного обратного прокси. Это допустимо только при запуске Gunicorn на loopback за Caddy, который формирует эти заголовки. Произвольный `X-Forwarded-Host` не принимается; проверка разрешённых доменов сохраняется.

## Установка на подготовленном Debian

Установить Python с venv, создать системного пользователя `competence-review`, каталоги из таблицы и виртуальное окружение. В окружение установить `requirements-server.txt`. Исходники копируются в новый каталог релиза; прежние релизы не перезаписываются. Файлы `competence-review.service`, `competence-review-backup.service` и `competence-review-backup.timer` устанавливаются в `/etc/systemd/system/`.

После проверки файлов:

```bash
systemctl daemon-reload
systemctl enable --now competence-review.service
systemctl enable --now competence-review-backup.timer
curl --fail http://127.0.0.1:8768/healthz
systemctl start competence-review-backup.service
```

Не требуется перезапускать Docker, NetBird или другие VPN-сервисы. Резервное копирование использует SQLite backup API и проверяет целостность копии без остановки приложения.

## Публичный адрес

До публикации нужен согласованный домен с DNS, указывающим на сервер. Домен записывается в `REVIEW_PUBLIC_HOST`, затем перезапускается только `competence-review.service`. Шаблон `Caddyfile.example` добавляется отдельным файлом в существующий каталог импортов Caddy с заменой домена. Существующие файлы сайтов сохраняются.

```bash
caddy validate --config /etc/caddy/Caddyfile
systemctl reload caddy
```

После этого проверить HTTPS, `/healthz`, вход организатора, персональную ссылку, сохранение и повторное чтение ответа. Конфигурация Caddy не добавляется автоматически до выбора домена. Если домена ещё нет, приложение можно проверить через SSH-переадресацию локального порта.

## Организатор и данные

Адрес кабинета: `https://<домен>/#admin`. Ключ создаётся при первом запуске в `/var/lib/competence-review/admin-access.txt`; передавать его следует через приватный канал или читать через SSH. В журнал его не выводят. Для запуска новой панели не нужно переносить локальные демо-ответы. На новом сервере создаётся пустая рабочая панель.

## Проверки и обслуживание

```bash
systemctl status competence-review --no-pager
journalctl -u competence-review --since today
systemctl list-timers competence-review-backup.timer
```

Резервная копия ежедневно запускается около 03:40 по времени сервера с небольшим случайным сдвигом. Копии на том же VPS помогают восстановиться после ошибки приложения, но не заменяют копии вне сервера. Дополнительно нужен внешний получатель: его адрес и доступ не хранятся в публичном репозитории. В текущем развёртывании можно забирать архивы на компьютер организатора через существующий SSH-доступ; такие копии обновляются только когда компьютер включён и подключён к нужной сети.

Для восстановления остановить только `competence-review.service`, сохранить повреждённый каталог отдельно, извлечь проверенный архив в каталог данных, установить владельца `competence-review` и права `0700` на каталог / `0600` на файлы, затем запустить сервис. После проверки восстановленной базы проверить вход и доступность последнего ожидаемого ответа. При обновлении кода сначала создать резервную копию, затем переключить `current` на новый релиз и перезапустить только приложение. Откат кода должен учитывать совместимость схемы базы.
